# Expansion batch H1-a: the 2006–2010 June drafts (prepared, not executed)

This is the first historical expansion batch: five June drafts (2006–2010), league-wide, all 30 clubs. It is **prepared
only**. Nothing has been downloaded for these years, and nothing may be until the permissions below are recorded.
`npm run history -- preflight --years 2006-2010` checks every grant without any request or write. It exits with code 4
while any is refused, which on 2026-10-21 is 30 of 45.

## Expected records and storage

| Measure | Estimate | Basis |
|---|---:|---|
| Phases | 5 (June regular only) | One phase a year since 1987 |
| Selections | ≈ 7,500 (1,450–1,550 a year) | Era estimate (50 rounds, 30 clubs, plus supplemental picks); replaced by the feed's count on discovery |
| Club-phases (coverage cells) | 150 | 30 clubs × 5 years (every club existed) |
| Players created | ≈ 7,400 | A few players are drafted in two of these years; each pick is its own acquisition |
| Field observations | ≈ 50,000 | 6.7 per selection, measured on the pilot |
| External ids | ≈ 17,000 | MLBAM for all; Chadwick ids for ≈ 99% (2005 pilot: 99.8%) |
| Storage | ≈ 70 MB (≈ 80 MB with research jobs) | ≈ 9.1 KB per selection, measured on the local pilot database including indexes: observations 4.3 KB, staging 2.5 KB, selection 0.8 KB, ids 0.7 KB, player 0.5 KB. Research jobs (`--no-plan` skips them) add ≈ 1.4 KB |

The hosted database is 30 MB today (2026-10-21), so the batch roughly triples it and stays well within the project's plan.
The explorer's synthetic benchmark (84,900 selections) bounds query time at this size: 13–35 ms per page and 0.3 s for
the deepest common page.

## Required source permissions

Each must be recorded in `research/history/sources.json`, as AUTHORIZED with the authorization document and its SHA-256,
or as CLEARED with a documented, legally reviewed basis. A person records these; tooling never changes a grant.

| Source | Uses needed | Today | Needed for |
|---|---|---|---|
| MLB Stats API | `fetch_bulk`, `process_local` (2006–2010) | PENDING / LIMITED to the pilot years | the selection universe: every pick, round, club and MLBAM id |
| MLB Stats API | `publish_site` (2006–2010) | LIMITED to 2015 on | putting the records on the public site |
| Independent per-club list (Baseball-Reference or another) | `fetch_targeted`, `process_local`; `publish_site` if its corroboration is published | Baseball-Reference: PENDING; bulk PROHIBITED | census claims. **Without one, all 150 club-phases stay partial reconstructions**, which is correct but never complete |
| Chadwick register | all | CLEARED | identity crosswalk |
| Wikipedia | `fetch_bulk` (5 requests) | LIMITED to 70 per run | draft dates and stated totals |

**Hosted, in addition:**
- one `ingest.historical_releases` row per year (025), citing the authorization reference;
- migration 025 deployed;
- the importer's hosted lock lifted by a reviewed code change.

## Compute and execution

- **Local:** build offline, then import with `--no-plan`. That takes about 5 minutes at the measured 25–30 records/s,
  plus integrity checks (about 2 s) and a read-model refresh (about 1 s).
- **Hosted:** the pipeline makes about 100 statements per record. From this server (110 ms round trip) that is about
  0.07 records/s, or roughly 30 hours, which is not acceptable. Run the same importer from a runner in AWS
  `ca-central-1` (about 1 ms round trip): about 0.15 s per record, so 20–30 minutes for the batch, one year per run with
  `--confirm-hosted`. A small instance for an hour costs well under $1.
- **Checks after each hosted year:** `hosted:parity`, `hosted:security`, `hosted:verify`, the integrity checks,
  `hosted:provenance` and a reconciliation against the local import (record by record, as for Wave 2).

## Expected reconciliation workload

Extrapolated from the 2005 pilot (one league-wide June draft, 30 clubs, all with an independent list):

| Exception kind | Per year | 2006–2010 | Review effort |
|---|---:|---:|---|
| Lists differ (a missing pick or a different player at a pick) | ≈ 1 | ≈ 5 | about 30 minutes each, with a third source |
| Name variants (pairs) | ≈ 100 | ≈ 500 pairs in 5 groups | mostly nicknames; a few seconds a pair, with care for unrelated first names: about 2 hours |
| Crosswalk unmatched | ≈ 3 | ≈ 15 in 5 groups | usually none (never played professionally) |
| Same person twice in a phase | 0 | likely 0–2 | about 30 minutes each |
| Numbering disagreements | 0 | 0 expected (modern numbering agrees) | — |

That is roughly 20 exception groups and 6–8 reviewer hours, recorded through `npm run history:review`. Without an
independent list, there is no list or name comparison at all, so the workload falls to the crosswalk groups. Every class
then stays partial.

## Deployment requirements

1. **Permissions recorded** (above), and `history -- preflight --years 2006-2010 --target local` passes. Add
   `--target hosted` before hosted.
2. **Local run:** `fetch-draft`, `calendar`, `fetch-evidence` (only if a permitted independent source exists), `build`,
   then `import --write --no-plan`. Outputs stay in `.restricted/history/`.
3. **Exception register:** `exceptions.mjs`, then `history:review -- load --propose-rules`. A reviewer decides the
   year's exceptions.
4. **Hosted** (only after `publish_site` is granted):
   - deploy migration 025;
   - add the release row for each year;
   - lift the importer's hosted lock in a reviewed PR;
   - run from the ca-central-1 runner, one year per run;
   - refresh the read models and run the checks.
5. **Vercel production** is a separate, manual release: `vercel.json` skips every Git-triggered production build.

## Stop conditions

Any of these stops the batch before the next write, with nothing half-applied (each batch applies in one transaction,
and runs resume from checkpoints):
- any permission refused (exit code 4), including a review date that has passed;
- a spent request budget (exit code 3; resume from the cache);
- a checksum mismatch in the cache (tampered or partial file);
- an invalid record, a held identity or a conflict in the dry run;
- a selection by a club that did not exist that year (database refusal);
- a historical year not released on the target database (025 refusal);
- **more than 2% of a year's picks** held or disputed, or **any** club with a count disagreement larger than 2 picks.
  This pauses the year for review before the next one;
- integrity, parity or security failing after a year; reconciliation with the local import showing any difference.
