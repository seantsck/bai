# Complete draft backfill plan, 1965–2026

This is a deterministic plan for every draft year. The per-year table is generated by `npm run history:plan` from the
committed manifest, the local cache and local coverage. The full plan, with every count, is written to
`.restricted/history/plan.json`.

**Permission gates apply to every step** (`research/history/sources.json`, enforced in code; see
[README.md](README.md#sources-and-permission-gates)). As of 2026-10-21:
- **No new MLB requests.** MLB's draft feed may not be fetched, in bulk or per class, until a person decides on its
  terms.
- **No Baseball-Reference archive collection.** Crawling archived pages is prohibited, and targeted reads await a
  decision.
- **Local processing only for the pilot years** (1965, 1985 and 2005), whose files were cached before the gates
  existed.
- **No publication of source-derived output to Git or hosted.** That covers selection lists, extracts and per-year
  counts derived from MLB or Baseball-Reference. They stay in `.restricted/history/`, which is gitignored, never
  deployed, and backed up outside the repository.

Until those decisions are recorded, this plan describes what *would* run. The importer refuses every step a gate does
not allow, with exit code 4.

## What is tracked, independently, per phase and club

| Measure | Where | Meaning |
|---|---|---|
| Expected selections | `coverage_assessments.expected_count` (census claims only); `rm_draft_year_coverage.expected_selections` | Set only when an independent list agrees with MLB's for that club. A year's total stays blank until every club that existed has one. |
| Imported selections | `draft_selections` | What BAI holds, whatever the coverage state |
| Resolved identities | `player_external_ids` (MLBAM, plus Chadwick ids) | Every imported pick has an MLBAM id; other systems where Chadwick has one |
| Signing status | `draft_signings` | No row means UNKNOWN (not researched), which is never "did not sign" |
| Bonuses known | `draft_signings.signing_bonus_usd` | Null means unknown, never zero |
| Outcomes audited | `outcome_audits` | NOT_AUDITED stays separate from AUDITED_NO_MLB |
| Complete vs partial | `coverage_assessments.coverage_state` | COMPLETE_CENSUS only with agreeing independent evidence; otherwise PARTIAL_RECONSTRUCTION with the reason |

`/draft/years` shows all of these per phase. No rates are published from any of them.

## Order of execution

| Wave | Years | Why this order |
|---|---|---|
| **H0** | 2015–2026 | Calendar exists (015). LAD and Wave 2 research continue under the existing research program. League-wide imports of these years use the importer like any other. |
| **H1** | 2014 → 2006 | One phase a year, strong identity coverage (birth dates on nearly every pick, Chadwick matches ≈ 99.8% in 2005), archived per-club pages likely. Proves the method at volume where evidence is strongest. |
| **H2** | 2005 → 1987 | One phase a year. Birth dates and crosswalk coverage fall going back. |
| **H3** | 1986 → 1976 | Four phases a year (January regular and secondary, June regular and secondary). More previously drafted players re-selected across phases. |
| **H4** | 1975 → 1965 | Four to six phases, the earliest numbering (pick numbers differ between compilers), and the lowest identity coverage. |

**Within a year (once its sources permit it)**
1. **Discover:** fetch every era phase (`fetch-draft`, needs `fetch_bulk` for MLB's feed), so empty phases are recorded
   too.
2. **Calendar:** add sourced phase rows, with a day only when a source states one; otherwise the month from MLB's phase
   name. Rows sourced from a restricted source stay in `.restricted/history/calendar.local.json`.
3. **Gather independent evidence** for census claims. That needs a source whose grants allow it; archived
   Baseball-Reference pages currently do not.
4. **Build** offline (`process_local` for every source of that year).
5. **Import** locally with `--no-plan`.
6. **Refresh** the read models.
7. **Run** the integrity checks.
8. **Commit** only the manifest (metadata). Batches, reports and the exception register stay restricted unless every
   source grants `publish_repository`.
9. **Review** the year's exceptions (`node scripts/history/exceptions.mjs`) before the next year.

**Stop conditions**
- A refused permission stops a run before any request or write (exit code 4).
- An invalid record, held identity or conflict stops a year before writing.
- A spent request budget stops a run without loss (exit code 3; it resumes from the cache).

## Requests and cost (once authorized)

| Source | Requests for the full plan | At the configured pace | Grant needed |
|---|---:|---|---|
| MLB draft feed | 159 discovery requests (6 a year to 1986, 1 a year after) | 1.5 s apart: about 5 minutes | `fetch_bulk` (PENDING) |
| Chadwick register | 16, once (cached) | done | CLEARED |
| Wikipedia | ≈ 62 (one revision per year, for dates and totals) | under 2 minutes | LIMITED to 70 per run |
| Independent per-club lists | ≈ 3,200 club-phase lists | depends on the source | none cleared yet (Baseball-Reference archive: PROHIBITED for bulk) |

- **Compute.** A local import of about 78,000 selections takes under 1 hour at the measured 25–30 records/s. The
  synthetic benchmark at that size keeps every explorer query under 0.4 s, and the read-model refresh at 3 s.
- **AI.** The importer makes no model calls. Review work is per exception (register entries), not per player.

## Hosted publication (gated)

The research pipeline makes about 100 statements per record. At the 110 ms round trip from this server, a
record-by-record hosted backfill would take weeks (the Wave 2 replay ran at about 0.07 records/s).

**Gates before any hosted historical import**
1. **`publish_site` for every source a batch cites.** It is enforced on hosted `research:import`, `research:validate`
   and `research:apply`, and by the history importer. For MLB's feed that needs written MLBAM authorization covering
   display, or a recorded decision that BAI's use is permitted. Batches that cite Baseball-Reference evidence (census
   corroboration) need a separate decision.
2. **Reviewed exceptions.** Every `UNRESOLVED` register entry for the year is decided by a person.
3. **A runner next to the database** in AWS `ca-central-1` (about 1 ms round trip, so 3–4 hours for everything), one
   year per run, with `--confirm-hosted`. After each year, run `hosted:parity`, `hosted:security`, `hosted:verify`, the
   integrity checks and `hosted:provenance`.

   A bulk path that bypasses the pipeline (copying tables) is **not** recommended: it would skip the identity,
   provenance and conflict guards.
4. **The importer's hosted lock.** It refuses hosted today; lifting it is a reviewed code change, not a flag.

## Historical international signings (parallel track)

- **Calendar.** International signing periods run from 2014-15 on the calendar. Earlier signings (the July 2 periods from
  2009, and year-round signing before) need their own rules eras and calendar rows, researched the same way.
- **No census.** No authoritative census exists for any period, so every international class stays
  PARTIAL_RECONSTRUCTION with an unknown size, however many records are found.
- **Sources.** MLB's transaction wire (subject to the same MLB terms decision as the draft feed; `scripts/research/sources/intl-signings-from-wire.mjs`), classified by the
  documented amateur rule, with unclassified signees listed rather than guessed. The wire's depth before the mid-2000s
  must be measured before planning years.
- **Separate track.** It runs separately from the draft waves and shares only the identity layer (MLBAM, Chadwick).
